      Why defensives show twice on party frames

      No spell list or rank tracking is involved. The Defensives group shows auras by Blizzard's own per-spell flags (HELPFUL|BIG_DEFENSIVE, HELPFUL|EXTERNAL_DEFENSIVE), so tracking a single rank wouldn't change anything.

      Most likely cause: with Which Auras set to Big and External (the module default), ModeUI adds two Blizzard aura groups, defensives1 and defensives2, one per flag (Modules/PartyFrames/AuraContainers.lua:118-122, AuraInit.lua:56-61). Blizzard's container checks every group's filter on its own (Blizzard_AuraContainerGroups.lua, UpdateAuraInGroups), so a defensive carrying both flags, or a spell that applies one aura per flag, fills both groups side by side. Blizzard's own raid frames avoid this: they show only the top big defensive and keep it out of the buff list (Blizzard_PrivateAurasUI.lua).

      Your saved profiles agree. In your live SavedVariables, the active profile is on Big Defensives. The saved Mode-Default and Default profiles are still on Big and External; that Mode-Default was built before round 7 switched the layout to Big only.

      Confirm in game (out of combat; aura fields are secret in combat)

      • /dump C_UnitAuras.GetUnitAuras("party1","HELPFUL|BIG_DEFENSIVE"), then the same with HELPFUL|EXTERNAL_DEFENSIVE. The same auraInstanceID in both lists means one aura is being shown by both groups. Two different IDs mean one spell applies two auras.
      • /dump C_UnitAuras.AuraIsBigDefensive(spellId) and /dump C_Spell.IsExternalDefensive(spellId) for the doubled spell. Both are in Forever's API documentation.

      Fix options

      • Settings only: set Big Defensives in the old profiles, or rebuild Mode-Default from its layout.
      • Code (recommended): when both flags are on, give the second group HELPFUL|BIG_DEFENSIVE|!EXTERNAL_DEFENSIVE. Forever's AuraUtil documents the ! negation prefix. Whether it works for these two flags inside a container is unverified. It needs no reading of secret aura data.
      • Like Blizzard: one center slot sorted by AuraContainerSortMethod.BigDefensive. A slot takes one filter string, so this covers one flag unless the split above is added.
      • Not workable: deduplicating by spell ID or name in Lua. Container aura data is secret in the world.

      The Healer layout hides Defensives for now, as you asked. The fix applies to every profile, so it is its own step in the plan.

      Implementation plan

      One focused, tested step at a time, each gated in game before the next. Work on branch t3/healer-layout, merged to main after the gate. The layout writes new profiles only, so nothing in Mode-Default or any existing profile moves.
