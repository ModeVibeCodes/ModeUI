ModeCDM does a lot, but every bar has to be tuned by hand

ModeCDM already covers more than most CDM addons: skinned Blizzard viewers, up to fifteen custom bars, spells by ID, items, racials, per-spell glows and text, resource bars and a cast bar. The weak spot is how it is set up. Each bar keeps its own copy of about 80 look settings and there is no shared style, so getting a consistent look means Copy & Apply or hand tuning. The settings come from three separate page builders whose labels have drifted apart. The proposal is a Bar Style, the default look for new bars (and existing ones if you choose), a smaller set of pages with More options folded away, and a short list of new features chosen on the Features tab.

Forever first, ready for a Midnight port

What Forever is

The modern (Midnight-era) client running the camelot game type, with classic-style classes and systems. Combo points sit on the target (Rogues, Druids in Cat Form). There are Shaman totems on the multi-cast bar, Hunter pet Happiness, weapon poisons and imbues, and a swing timer API (C_SwingTimer) Retail doesn't have. No Evokers or Retail class resources. Secret values apply as on Retail.

What was checked

Forever's own UI source (forever branch, 1.60.1). Its Cooldown Manager is Retail's code: 20 of 27 files are identical. The other 7 add Forever's item category cooldowns (potions show the last one used) and an Edit Mode refresh. So Blizzard's alert editor, group buffs, layouts and the equipment-slot categories are in Forever's files too. Whether Forever's game data fills them is checked in game.

Rules for this pass

Build only on what Forever's own source has. Each feature is tagged Forever only, Forever + Midnight, Check in game, or Retail-centric; Retail-centric ones are skipped. Forever-only features check that their API exists and step aside when it doesn't. A Midnight port then drops them cleanly instead of breaking. See Port groundwork on the Plan tab.

What stays

These carry over unchanged in behavior. The rework changes how they are set up, not what they do.

  • keep Custom Cooldown and Buff bars, including the five default bars (Defensive Cooldowns, Emphasized, Left, Right, Ultra)
  • keep The preview with click-for-menu and drag-to-reorder
  • keep Spells by ID, items, racials; per-spell glow and text looks
  • keep Resource bars (Group Resources, tick marks, Dark mode) and the Cast Bar
  • keep Blizzard decides what is tracked; ModeUI only places, skins and lights it
  • keep Saved keys, the Mode-Default and Healer layouts, and the secret-value rules

My recommendation

Layout stage + one scroll with an index

The stage shows every bar in place, with the one you're editing outlined; click another bar to switch. Below it, one scrolling page with a section index, a Bar Style chip on each section and a More options fold. A Bar only toggle zooms the stage onto the selected bar for clicking and dragging spells. Quick cards become the Home page, and Test on Screen covers true placement. Drawn to scale at the window's real size (1060 × 740).

Implementation plan

Phases follow AGENTS.md: design doc first, then Style, then the module. Every settings change is a migration that keeps your values. A new default only replaces values still at the old default. Phases tied to features marked Skip are dimmed. Nothing here starts until you say so.

Port groundwork (applies in every phase)

Forever is the target. These rules keep a later Midnight port to a packaging change plus table entries, not a rewrite. No Retail package is built in this pass.

  • Check the API, not the client. Caps.lua (phase 1) records what the client offers; every feature and settings row reads M.caps. Nothing below the edition gate asks "is this Forever?".
  • Forever-only features live in their own files (SwingTimer.lua, WeaponEnchants.lua, PetBar.lua) and register their Player Bar only when their cap is true. On Midnight they simply don't appear.
  • One edition gate. ModeCDM/Modules/CooldownManager/Init.lua:3 returns unless the edition is Forever. ModeUI's Shared/Runtime/Core.lua already knows a "Retail" edition (WOW_PROJECT_MAINLINE), so a port changes that one check and the TOC metadata (## Interface, X-ModeUI-Edition). Both stay Forever-only for now.
  • Class resources come from data. Resources.lua takes the name and maximum from Shared/Domain/ClassResource.lua's CLASSES table instead of assuming combo points, so Retail resources (Holy Power, Chi, Runes, Essence, Soul Shards) become table entries in a port. The saved key stays combo.
  • Saved settings are the same on both clients. A feature whose API is missing keeps its saved keys and validation; it just doesn't show. No migration depends on the client.
  • Blizzard's Cooldown Manager is shared code, so the hooks, Bar Style and pages work on both unchanged. Forever's one CDM difference (category cooldowns) is read, not relied on.
  • Tests run the mock once with the Forever-only APIs removed, to prove those features step aside cleanly.
