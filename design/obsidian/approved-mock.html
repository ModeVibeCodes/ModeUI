Research

How hard is a new theme, this soon after the redesign?

Less than it looks. The redesign was mostly about moving every color, border, bar texture and font into one place, ModeUI/Shared/Style/, with a test (tests/design.lua) that fails if a module hard-codes any of them. That is exactly the seam a new theme needs. Counts are from the repository as it stands today.

Blank slate or build on today's ModeUI

Start a new addon

  • Rebuilds behavior, not looks: secure frames, secret-value handling, aura containers, 8 modules' migrations, 35 tests and the 4,490-line settings window.
  • ModeUIDB can't carry over without an importer, and the project rule is never to reset it.
  • Two addons, or two code paths, live side by side until the new one catches up. That is the overlap you're worried about, made worse.
  • The only real gain is freedom from old defaults, and migrations already handle that.

Build on today's ModeUI (recommended)

  • The look is about 5% of the code, already isolated, and guarded by a test.
  • Obsidian arrives as a new border style beside Mode-Blizz, so you can switch back and forth in game before anything becomes a default.
  • Old and new don't tangle: the test keeps every visual in Style, and Phase 8 already showed how to delete a retired look cleanly.
  • Every step is one focused change that you can check in game.

Build on the existing addon. The redesign is the reason this is cheap: it built the theme seam. A blank slate would spend most of its effort rebuilding behavior that already works.

If you go ahead

An order of work

  1. Design doc first. Add Obsidian, the Dark bar mode, the glow and Backlit dispels to docs/DESIGN_LANGUAGE.md, per the project rules.
  2. Obsidian border style and ring art. It appears in every Border picker and the Ring Style picker. Nothing else changes, so you judge it in game beside Mode-Blizz.
  3. Dark bar mode in Style.Bar, then offered by Unit Frames, Party Frames, Nameplates and ModeCDM.
  4. Backlit dispels in Party Frames: a bottom-anchored option for the existing Gradient effect.
  5. Prism glow for mouseover and focus.
  6. Theme switch (Dark default, Color option) and the migrations that move untouched defaults to follow it.
  7. Retire Mode-Blizz pieces only if you no longer want them as options. Until then they cost nothing.
Research only. Nothing in the ModeUI repo changed. Portraits and icons are placeholders. The sizes are relative, not time estimates. The sheen, glow and blend calls need an in-game check on Forever.
