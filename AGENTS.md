# ModeUI — Forever only

- This repository is the home for Mode's custom interface modules for WoW Forever.
  Edit the addon in `ModeUI/`; companion addons sit beside it and need it. The
  first is `ModeCDM/` (the Cooldown Manager; the owner named it): its module
  runs inside ModeUI's addon table (ModeUI-Core `Companion`), keeps its
  settings in `ModeUIDB` and nests under ModeUI in the AddOn list
  (`## Group: ModeUI`). See "Companion addons" in `docs/ARCHITECTURE.md`. Play
  The Game Tools is a separate addon and repo.
- **The Mode redesign is built (Phases 0-8, November 15, 2026).** Next is the
  owner's revisions and tweaks phase; the Phase 9 release only on the owner's
  word. Status, decisions and history are in `docs/MODE_REDESIGN.md`; read it
  before continuing.
- **The look is the Mode design language, `docs/DESIGN_LANGUAGE.md`.** Every
  color comes from `Style.Tone`, every border from a `Style.Edge` preset, every
  bar from `Style.Bar` (Mode BG empty part, Comet spark, Combined shields),
  every texture from a "Mode <Name>" key in `Style.Asset`, every font from
  `Style.Font` (the Mode typeface: Expressway when installed, else Geist). All of it lives in `ModeUI/Shared/Style/`; modules,
  Skin and Settings never hard-code colors, borders, masks, texture paths or
  font files. Change the design doc first, then Style, then the modules.
- `tests/design.lua` enforces that, everywhere outside `Shared/Style/` and
  `Libs/`. `tests/design_legacy.lua` (the pre-standard files) is empty since
  Phase 8; never add a file there. A color a module needs becomes a
  `Style.Tone` token (or a `Style.LEGACY` entry for an old default a migration
  recognizes); a frame's shape mask goes through `Style.SetShapeMask`, a bar's
  fill file through `Style.SetBarTexture`, colored text through
  `Style.ColorText`.
- New Mode art is generated by `tools/build_mode_assets.lua` (Lua, no Python):
  power-of-two 32-bit TGA under `Media/Textures/Mode/`, registered with
  LibSharedMedia as "Mode <Name>". Borders use sliced rim art, never masks.
- The settings window uses the Mode theme only. Keep new pages on the shared
  widgets in `Shared/Settings/` so they inherit it; a module declares
  `layout = "split"` (live preview) or `"page"`.
- Preserve functionality, appearance, settings and saved-variable keys unless
  the user asks for a specific change. Never reset `ModeUIDB`; migrate instead.
  A new default only replaces values still equal to the old default.
- Read the relevant source before editing, and implement one focused feature at a time.
- Research uncertain APIs in current Blizzard source and docs. Never invent APIs,
  bypass restrictions, or assume Retail behavior applies to Forever. Unit values
  can be secret: pass them only to widgets documented as accepting them.
- Secure frames are created, shown, moved and resized outside combat only.
- Mode borders need no masks. (Should a mask ever be needed: a texture holds
  at most 3; a 4th `AddMaskTexture` errors and stops ModeUI loading.)
- Follow `docs/ARCHITECTURE.md`. New code goes in `Libs/`, `Shared/` or
  `Modules/<Name>/`. Each module is a
  folder with `<Name>.xml` (listed in the TOC), `Init.lua` loaded first, and
  `Driver.lua`. Code two modules need belongs in `Shared/`; modules never use each
  other's files. Files stay under 400 lines. Settings pages are built only when opened.
- Keep `ModeUI/ModeUI.toc` and each companion's TOC load order correct (a
  companion loads `Core.lua` first and `Start.lua` last). No placeholder
  functionality.
- Run every test: `lua tests/<name>.lua` for each file in `tests/` except
  `harness.lua`, `wow_mock.lua`, `design_legacy.lua` and the `*_stubs.lua` helpers.
  New modules start from `docs/module-template`. Do not claim native testing without
  the user's in-game confirmation.
- Manual checks must state Navigation, Action, Required state and Confirmation,
  using the actual control labels. Do not invent UI paths.
- Releases, pushes and collaborator invitations need the user's authorization.
- Preserve licenses and notices. Never force-push or reset.
